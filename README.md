# GA4-E-Commerce-Product-Analytics-A-B-Testing

An end-to-end A/B testing and product analytics pipeline built on Google Analytics 4 (GA4) e-commerce event data. The project takes raw GA4 export data from BigQuery, runs a full statistical inference workflow on an experiment (Control vs. Treatment), and surfaces the results in both a Jupyter notebook (analysis) and an interactive Streamlit dashboard (reporting).


---

## Project Overview

The goal of this project is to answer a standard product question: **did the Treatment experience move conversion, and is it safe to ship?**

It does this by combining:
- A **BigQuery → pandas** data pipeline for pulling GA4 e-commerce event data
- A **custom A/B testing engine** (`GA4ABTestingEngine`) implementing sample-size planning, two-proportion z-tests, CUPED variance reduction, and guardrail metric checks
- A **Streamlit dashboard** (`dashboard.py`) that re-runs the same statistical logic on an uploaded or bundled CSV and presents it as a live, shareable report

## Data

Each row represents a single user session pulled from a GA4 BigQuery export, with the following fields:

| Column | Description |
|---|---|
| `user_id` | Pseudonymous GA4 user identifier |
| `device_category` | Device used (desktop, mobile, tablet) |
| `traffic_medium` | Acquisition channel (organic, referral, none, etc.) |
| `hit_session` | Session occurred (1/0) |
| `hit_view_item` | User viewed a product (1/0) |
| `hit_add_to_cart` | User added an item to cart (1/0) |
| `hit_checkout` | User reached checkout (1/0) |
| `converted` | User completed a purchase (1/0) — primary metric |
| `total_revenue` | Revenue generated by the session |
| `experiment_variant` | `Control` or `Treatment` assignment |

The dataset used in this analysis contains **109,495 sessions** (54,552 Control / 54,943 Treatment).

## Methodology

### 1. Primary Metric — Two-Proportion Z-Test
Purchase conversion (`converted`) is compared between Control and Treatment using a pooled two-proportion z-test:

- Pooled standard error under H₀: p_control = p_treatment
- Z-score and two-tailed p-value from the normal distribution
- 95% confidence interval on the absolute difference in conversion rates
- Significance threshold: **α = 0.05**

### 2. Variance Reduction — CUPED
To increase sensitivity to a true effect, the engine applies **CUPED (Controlled-experiment Using Pre-Experiment Data)**, using `hit_add_to_cart` as a pre-conversion covariate correlated with the outcome:

```
converted_cuped = converted − θ × (hit_add_to_cart − mean(hit_add_to_cart))
θ = Cov(converted, hit_add_to_cart) / Var(hit_add_to_cart)
```

A Welch's t-test is then run on the CUPED-adjusted outcome, and the reduction in outcome variance (raw vs. CUPED) is reported as a measure of how much noise was removed.

### 3. Guardrail Metric — Average Order Value (AOV)
Since conversion rate alone can hide harmful side effects (e.g., a variant that converts more but degrades basket size), AOV among converting users is checked as a guardrail using a Welch's t-test. A guardrail "fails" only if AOV is **both** statistically lower in Treatment **and** p < 0.05 — i.e., a higher or non-significantly different Treatment AOV does not trip the alert.

### 4. Funnel Diagnostics
Session → view item → add to cart → checkout → converted is aggregated per variant and visualized as a grouped bar chart to check where (if anywhere) the funnel diverges between groups.

### 5. Sample Size Planning
`calculate_sample_size()` uses `statsmodels`' `NormalIndPower` to back out the minimum sample size needed to detect a specified minimum detectable effect (MDE) at a given power/alpha, useful for scoping future experiments.

## Results

| Test | Control | Treatment | Result |
|---|---|---|---|
| Conversion rate | 1.03% | 0.96% | **−6.88% relative lift**, z = −1.18, p = 0.2366 → **not significant** |
| CUPED-adjusted conversion | — | — | 13.99% variance reduction, p = 0.3633 → **still not significant** |
| AOV (guardrail) | $47.30 | $56.97 | p = 0.0267 (significant), but Treatment AOV is **higher** → **guardrail not tripped** |

---

## Conclusions

1. **No statistically significant effect on conversion.** The Treatment showed a directionally negative but statistically insignificant change in purchase conversion (95% CI on the difference includes zero). We cannot reject the null hypothesis that Control and Treatment convert at the same rate.
2. **CUPED did not change the conclusion.** Even after removing ~14% of outcome variance using pre-experiment cart behavior, the effect remained non-significant — suggesting the null result isn't simply a power/noise problem, though a larger sample or longer runtime could still be warranted to detect a small true effect.
3. **No guardrail violation.** Average Order Value was significantly *higher*, not lower, in Treatment, so the experiment shows no evidence of revenue-quality degradation.
4. **Recommendation:** Based on this dataset, there isn't sufficient evidence to ship the Treatment on conversion-rate grounds alone, but there is also no evidence it harms revenue per order. A next step would be to use `calculate_sample_size()` to determine the sample needed to detect the observed ~7% relative effect with adequate power before deciding whether to extend the test or conclude it as neutral.

## Running the Project

### Notebook
```bash
pip install google-cloud-bigquery pandas numpy scipy statsmodels plotly nbformat db-dtypes
jupyter notebook GA4_data_analysis.ipynb
```
Requires either a BigQuery connection (for live GA4 export data) or a local `ga4_experiment_data.csv` matching the schema above.

### Dashboard
```bash
pip install streamlit pandas numpy scipy statsmodels plotly
streamlit run dashboard.py
```
On launch, the app looks for `ga4_experiment_data.csv` in the working directory; otherwise, upload a CSV with the same schema via the sidebar.
